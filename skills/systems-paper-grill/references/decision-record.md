# Paper Decision Record

Use one current-state record per paper, named paper-decisions.md in the author-designated paper project, or use an explicit author-selected path. The record belongs to the paper, not to the installed skills or this skill-source repository.

## Choose and preserve the writable object

An explicitly named paper project permits the default record there when paper discussion with recording is requested. For pasted text, an ambiguous project, or a named manuscript file without a record location, ask where to save the record before writing it. Discussion can proceed in chat meanwhile. Filesystem accessibility alone is not permission to select a project.

Read the existing authorized record before editing. Preserve unrelated decisions and author text; merge information into the same issue instead of appending duplicate rounds. Create the file only when there is substantive content. Use [the template](../assets/paper-decisions-template.md) for new entries; leave unrelated existing entries in their original format. State each decision, reason and open question once in a short paragraph, rather than repeating them under problem, proposal, question and confirmation fields. Persist partial answers and open questions as pending; a partially resolved discussion need not wait until the final round to be saved. After each update, read back the changed entries and check that they match the author's answer, preserve unrelated decisions, and were written to the agreed path before reporting them saved.

## Record the decision, not the transcript

For each substantive issue, use a short entry: an ID and status, an original-text anchor, then a brief paragraph explaining the problem, author's decision, reason and allowed edit. Add the actual evidence basis and confirmation in concise prose. Pending questions and rejected proposals remain worth saving even when they are not major design decisions. Routine grammar fixes need no separate entry unless they clarify an agreed edit. These are agent-managed notes, not a form for the author:

- `pending`: the author has not confirmed the proposal, or multiple interpretations remain.
- `confirmed`: the author explicitly selected the meaning and allowed action recorded here. State the confirmation basis in a short paraphrase or quote.
- `rejected`: the author declined the suggestion. Retain the rejected action and its reason when useful to prevent reintroduction.

Track evidence separately as `supported`, `missing`, or `conflicting`, with the actual basis. A confirmed intention with missing evidence is not an executable factual addition. Author-supplied implementation facts can be attributed as such; agreement with an assistant's guess does not establish an experiment, proof, or measured result.

Keep confirmed terminology and scope boundaries alongside the decision they clarify. Capture the reason and any materially rejected alternative, not every question and answer. No dates, version headings, change log, or chronological transcript. Explicitly superseded decisions are updated in place after confirmation; silently changing the author's decision is not maintenance.

Record durable decisions, not transient session restrictions such as "the manuscript is currently read-only in this discussion". Grill's read-only manuscript boundary belongs in its instructions; the record should state the author's allowed future edit. Revise still needs an actual revision request before acting.

## Read the record during revision

The author-authorized record is editorial input, never manuscript text or a higher authority than a newer explicit author correction. Revise reads it with the original manuscript and any supplied Review findings, then applies only confirmed, evidence-compatible decisions to their authorized locations.

Match locations using both anchors and meaning; paragraph numbers can change. If the current text already satisfies the decision, leave it intact. If an anchor no longer matches, decisions conflict, or the permission or evidence is unclear, ask only about that issue and leave the affected text unchanged. Never broaden a confirmed local edit into a paper-wide rewrite.

Revise does not silently rewrite the decision record to agree with its output. Report a newly discovered conflict back to Grill. Review remains read-only even when the record is supplied. Neither skill reads a record outside its authorized scope; when continuing in a new task, request the original manuscript and record if they are unavailable.
